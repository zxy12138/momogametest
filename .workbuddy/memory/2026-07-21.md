## 续2：修复 `AnimatedSprite2D.frames` 运行期报错（Godot 3→4 改名坑）

用户 F5 运行报：`Player._anim_update: Invalid access to property or key 'frames' on a base object of type 'AnimatedSprite2D'`（Player.gd:100）。

### 根因
Godot 3 的 `AnimatedSprite/AnimatedSprite2D` 属性叫 `frames`；**Godot 4 改名为 `sprite_frames`**。本项目 5 处动画赋值/读取用了旧名：
- `GameManager.gd:230` `asp.frames = sf`（特效 AnimatedSprite2D.new()）
- `Player.gd:33` 赋值、`Player.gd:100` `_sprite.frames.has_animation(next)`
- `Enemy.gd:47`、`Boss.gd:38` 赋值

运行期访问不存在的 `frames` 抛 `E` 级错误（**非致命**：只中断当前方法、游戏继续跑，所以上一轮 headless 测试只看 RT_OK 被漏掉）。

### 修复
5 处 `.frames` → `.sprite_frames`（节点均为 AnimatedSprite2D，原代码也调 `.play()` 佐证）。

### 验证教训（重要）
- 之前 headless 测试只校验 `RT_OK`，但 `.frames` 这类运行期 `E` 错误**不阻断 RT_OK**（非致命），会漏检。
- 正确做法：headless 跑进战斗房让玩家/敌人每帧触发动画，再 **grep 日志里的 `Invalid access` / `E ` / `SCRIPT ERROR`**，而不只是看退出码/RT_OK。
- 本次修复后重测：临时 autoload 进 `r2` 战斗房跑 3 秒，日志仅引擎横幅 + `CHK_DONE`，零 `E`/零 SCRIPT ERROR。交付配置（入口 Main）启动亦零报错。临时文件已清。

### 关于用户标注 `[忽略]` 的告警
NARROWING_CONVERSION（float→int 收窄，Player 92/96/139/144）与 SHADOWED_VARIABLE_BASE_CLASS（187 行参数 `name` 遮蔽 `Node.name`）属**告警级**，用户标注 `[忽略]`，且项目配置已将其忽略（此前 headless 解析通过可证），非阻断，本次未动。
