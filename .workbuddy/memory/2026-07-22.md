## 修复 Weapon._do_fire 的 roll_crit 报错 + 默认分辨率改 1080p

### 1. 报错：`Weapon._do_fire: Nonexistent function 'roll_crit' in base 'Node (GameManager.gd)'`
- 根因：`Weapon.gd:39` 开火时调用 `GameManager.roll_crit()` 掷暴击，但 `GameManager` 里只有暴击**状态变量**（`crit_rate` / `crit_dmg` / `extra_crit_flat` 等，在 `compute_stats()` 里维护），**从没定义过 `func roll_crit()` 这个函数**。
- 修复：在 `GameManager.gd` 的 `compute_stats()` 之后补 `func roll_crit() -> bool: return randf() < crit_rate`。`crit_rate` 即最终暴击率（含等级 + 词条加成，已 clamp 到 0..1），与 HUD 显示的「暴击 X%」一致。
- 验证：临时 autoload 进战斗房 r2（玩家持 staff 远程），`Input.action_press("attack")` 连开火 3 秒，日志 `ROLL_TEST=false type=1`（函数存在、返回 bool），零 `E `/零 `SCRIPT ERROR`。

### 2. 默认分辨率 → 1920×1080 窗口
- `project.godot`：`window/size/viewport_width` 960→1920、`viewport_height` 540→1080。
- **连带修正画面比例**：游戏原按 960×540 取景设计，直接拉大视口会让相机 zoom=1 时看到 2 倍世界范围（缩小）。故在 `Player.tscn` 的 `Camera2D` 加 `zoom = Vector2(2, 2)`（Godot 4 的 `Camera2D.zoom` 是 **Vector2**，非 Godot 3 的 float），使 1080p 下取景与原 960×540 完全一致，只是更清晰、窗口更大。
- 验证：上面战斗房测试即是在 1920×1080 视口 + 相机 zoom 2 下跑的，玩法正常；交付配置（入口 Main）启动也零报错。

### 遗留（非阻断，按需）
- 武器数据 `Weapons.gd` 每把有 `crit_bonus` 字段（0.0~0.05），但当前 `roll_crit()` 只用全局 `crit_rate`，**未把武器自身暴击加成算进去**。若要做满，把调用改成 `GameManager.roll_crit(w.get("crit_bonus", 0.0))` 并在函数里 `randf() < crit_rate + bonus` 即可。用户未要求，本次未动。

### 修复：上移消失 / 武器不在手 / 弹道不显示 / 无地图指引
（用户 3 条反馈一并处理）

1. **上移角色「消失」**：根因不是相机（诊断证实相机跟随正常，cam.y 始终 = player.y），而是 Y 轴排序：`Player/Enemy/Projectile` 都用 `z_index = int(global_position.y)`，上移 y<0→z<0，被 `Room.tscn` 的 `Floor`（ColorRect，默认 z=0）盖住→隐形；下移 z>0→回到地板前→重现。修：`RoomManager._build_floor` 里 `_floor.z_index = -4000`（Godot z_index 合法范围 [-4096,4096]，-10000 越界报错；-4000 仍在所有实体 y∈[-250,250] 之下，永久最底层）。
   - 验证：诊断 `up y=-213 z=-213`（z 仍变负，但地板已沉底不再遮挡）。

2. **武器不在手上**：`Weapon` 是裸 `Node2D`，无视觉子节点（诊断 `wpn_children=[]`）。修：`Weapon.gd` 加 `Sprite2D` 子节点（`_make_held` 用 `load_tex(weapon.icon)` 设贴图，武器切换重建，`_update_held` 每帧按 `aim.x` 翻转 + 偏移到手位 `(12*face,-2)`）。

3. **远程弹道不显示**：诊断发现弹道生成了但 `Sprite.texture==null`→隐形。根因 `Weapon._spawn_proj` 把 `p.set("texture_path",...)` 写在 `_spawn(p,pos)`（内部 `add_child` 触发 `_ready` 加载贴图）**之后**，导致 `_ready` 时 `texture_path` 还是空串。修：所有 `set()` 移到 `_spawn` 之前（`Enemy._spawn_proj` 本来顺序就对，无需改）。
   - 附带：敌人弹道此前也隐形，根因 `Enemies.gd` 的 proj 路径 `B+"../weapons/projectiles/..."`（`B="res://assets/sprites/bosses/"`）解析成 `res://assets/sprites/weapons/...`（错的，应为 `assets/weapons/...`）。修：改成和玩家 `Weapons.gd` 一致的干净绝对路径 `res://assets/weapons/projectiles/`。同时 `GameManager.load_tex` 从 `ResourceLoader.exists()+load()` 改为直接 `load()`（`exists()` 不规范化 `..` 路径，会误判失败）。

4. **无地图/门指引**：`RoomManager._build_doors` 只造了隐形 `Area2D` 门碰撞体。修：每道门加发光门框+传送光柱（`ColorRect`，cyan，z=4/5）+ 方向箭头标签（`↑/↓/←/→` + 目标房类型，`_room_label` 把 type 映射「战斗/精英/BOSS/驿站/起点/房间」）；Boss 通关后「下一层」传送门（`Game._spawn_next_door`）同样加可见指示；驿站加「驿站」标签。

### 踩坑
- `MapUI.gd` 编辑时我的替换字符串把 `_close()` 函数定义**重复写入**（原 77 行已有一份，又在 152 行插了一份），导致 `Parse Error: Function "_close" has the same name as a previously declared function`，整张地图 UI 加载失败（按 M 无地图）。修：删掉重复的那份（保留 `toggle_map` 调用处引用的原 `_close`）。**教训**：对已有同名函数定义的文件做「函数 A + 函数 B（同名重复）」式拼接编辑极易出此错；编辑前先用 Read 确认目标函数是否唯一，且替换字符串务必只覆盖一次性出现的锚点。
- 诊断脚本里用 `p.name != "RoomManager"` 判断敌人是否挂在房间下是**误判**——场景节点名是 `Room`（脚本 class_name 才是 RoomManager）。正确判据用 `p.has_method("setup")`（RoomManager 才有）。
- **动态 UI 必须挂 CanvasLayer（屏幕空间），不能挂相机节点**：`Game` 是受 `Camera2D`(zoom=2 + 跟随玩家）影响的 Node2D。把驿站面板/ESC 暂停菜单/升级三选一/`toast`/提示/`dev` 标签用 `add_child` 直接挂到 `Game` 下，会按**世界坐标**渲染；而定位用的 `get_viewport_rect().size/2`（"屏幕中心"）在相机变换下被推到屏幕外 → 看起来"窗口没弹出、按钮没反应"。只有恰好在世界原点附近的 F 提示碰巧可见。修：给 `Game` 加专用 `CanvasLayer`(`UILayer`, layer=10），所有动态 UI 改挂它；定位改用 `get_window().get_visible_rect()`（屏幕坐标）。HUD/MapUI 本就是 CanvasLayer 所以正常，也印证此判断。
- **诊断 autoload 自身也要过严格模式**：`var par := inn.get_parent()` 里 `inn` 是 `g.get(...)` 返回的 Variant，`get_parent()` 无法推断类型 → `Parse Error: Cannot infer the type` → 整个 autoload 加载失败 → 游戏主循环空转不退出（进程挂住）。GDScript 2.0 严格模式下对 Variant 结果一律显式标注类型（`var par: Node = inn.get_parent() as Node`）。

## 修正：F2 开发者模式无效 + 地图内 ESC 行为
（用户反馈："F2还是没有效果"，"M打开地图时，ESC是返回，而不是再弹出一个选项框"）

### 1. F2 无效根因 = 键码填错
- 之前 `project.godot` 的 `dev` 动作键码填的是 `4194320`，但那是 **`KEY_KP_0`（小键盘 0）**，**不是 F2**！真正的 F2 = `4194305`（`KEY_F1=4194304`，累加）。所以 F2 永远匹配不上 → 开发者模式开关压根没触发。
- 修：`dev` 动作的 `keycode` 和 `physical_keycode` 都由 `4194320` → **`4194305`**。
- 备注：上面"四合一修复"段落里写的 `dev(F2, keycode 4194320)` 是**错的**，以此为准纠正。MEMORY.md 那条键码坑也已改成正确值。

### 2. 地图里按 ESC 弹暂停菜单（应为"返回"）
- 根因：`Game._unhandled_input` 处理 `ui_cancel`(ESC) 时只判断了驿站/暂停，**完全没看地图是否开着**；而 `MapUI` 只监听 `M`、不处理 ESC。于是地图打开时按 ESC，Game 走 `else` 分支把暂停菜单弹出来了。
- 修：
  - `MapUI.gd` 新增公开方法 `is_open() -> bool` 和 `close_map() -> void`（内部调 `_close()`）；并把地图标题提示从「按 M 关闭」改为「按 M 或 ESC 关闭」。
  - `Game.gd` 的 `ui_cancel` 分支改为：驿站开→关驿站；**地图开→`MapUI.close_map()` 直接返回**；暂停开→关暂停；否则→开暂停。
  - 实现细节：用 `var mu: Node = get_node_or_null("MapUI")`，经 `mu.has_method(...)/mu.call(...)` 动态调用（避免把 mu 当 Node 静态调用 `is_open()` 触发严格模式类型报错）。`MapUI` 在 Game.tscn 里是 Game 的直接子节点，`get_node_or_null("MapUI")` 能找到。
- 无冲突：地图只听 `toggle_map`(M)，ESC 只由 Game 处理，单向控制，不会双重触发。
