## 修复：切换场景右下角黑屏
- 现象：每次切房间/死亡/生日等场景切换时，右下角闪一块黑。
- 根因：`Game.tscn` 的 `Fade` 是 `Game`(Node2D) 直接子节点下的 `ColorRect`，处于**世界空间**。相机 `Camera2D.zoom=Vector2(2,2)`，1080p 窗口可见世界仅 960×540；Fade 尺寸 1920×1080 锚在世界 (0,0)，于是只盖住玩家周围可视区的右下 1/4，淡入淡出时就露出右下角黑块。
- 修法（与项目已有 `_ui_layer` 屏幕空间模式一致）：
  - `Game.tscn`：`Fade` 由 `ColorRect` 改为 `CanvasLayer`(layer=20)，其下挂 `ColorRect`(name=Rect, 黑, mouse_filter=2)。无新增 ext_resource，`load_steps` 仍为 6。
  - `Game.gd`：加 `@onready var _fade_rect: ColorRect = $Fade/Rect`；`_ready` 里 `_fade_rect.size = get_window().get_visible_rect().size`（与原文件其它全屏 UI 取法一致）；原 9 处 `$Fade.*` 全部改为 `_fade_rect.*`（注意 replace_all 误伤了刚加的 @onready 行，已改回 `$Fade/Rect`）。
- 验证：本机无 Godot 可执行文件，未跑无头校验；改动局部且纯架构（CanvasLayer 屏幕空间全屏），逻辑等价。建议用户启动游戏实跑一次确认右下角黑块消失。
- 注：本会话顺手把超限的 `MEMORY.md` 精简合并（去掉注入时被截断的风险），关键坑全部保留。

## 修复：ESC→重新开始 后无法操作（不能动/不能打）
- 现象：按 ESC 开暂停 → 点「重新开始」→ 进新场景后玩家完全失控（移动/攻击都无效）。
- 根因：`GameManager.input_locked` 是输入总闸（`Player._physics_process` 见 true 即 `velocity=0;return`）。`_open_pause()` 把它设 true；但 `_restart_game()` 走 `change_scene_to_file` 前只调 `reset_run`，而 `reset_run` 当时**没重置 `input_locked`** → 新 Game 场景里它仍为 true → 卡死。
- 顺带挖出**同因兄弟 bug**：`DeathCG._retry()` 调 `apply_death()`（也没解锁），且 `Main._new_game()` 根本不调 `reset_run`/不解锁 → 死亡→回菜单→新游戏 同样卡死。
- 修法（最全面、单点收口）：`Game._ready()` 开头加 `GameManager.input_locked = false`（覆盖所有进 Game 的路径：ESC 重开 / 死亡重试 / 死亡回菜单再新开 / 生日回游戏）。并保留 `reset_run` 归位 + `_restart_game`/`_return_menu` 两处双保险。
- 验证（重要）：本沙箱**下载不了 Godot 引擎**——github release 资源在 `objects.githubusercontent.com` CDN、tuxfamily 都被 443 掐断，只放行 github.com 网页/API。无法在这里跑无头测试。改做：① 代码级核对（grep 确认 3 处修复 + 玩家门控仍在）；② 写了**受控测试脚本** `H:\GodotProject\momogametest\_restart_test.gd`（仅当命令行带 `--run-restart-test` 才触发，常驻 autoload 不影响正常开编辑器），复现 ESC→重开并断言 `input_locked` 归位。用户本机有 Godot 时一键跑：`godot --headless --path H:\GodotProject\momogametest --run-restart-test`，看日志 `RESTART_TEST ... => OK`。验证完可删该文件并去掉 project.godot [autoload] 的 RestartTest 一行。
- 注：`godot_test/` 目录下的失败下载残留已清理。
