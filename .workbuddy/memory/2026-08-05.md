## 修改·装饰素材进游戏闭环（补36）
- 需求延续补35③：用户要在游戏场景内可视化放置序列帧动画且运行期正确显示。根因：RoomLayoutEditor 是 @tool 工具场景，从插件素材库拖入的 .tscn 只是它的临时子节点实例，未进 RoomLayout 数据，运行期 RoomManager 看不到→不显示。
- 方案（数据驱动，贴合现有 enemy_placements 模式）：
  - 新增 `src/rooms/DecorationPlacement.gd`：`scene_path:String` + `pos:Vector2`（同 EnemyPlacementDef）。
  - `RoomLayout.gd` 加 `decorations: Array[DecorationPlacement]`。
  - `RoomManager.gd` 加 `_spawn_decorations()`：遍历 `_layout.decorations`，`ResourceLoader.exists` 守卫→`load().instantiate()`→`global_position=pos`/`z_index=int(pos.y)`/`add_child`；在 `setup()` 末尾调用，**所有房间类型（含 inn/boss）都实例**，随房间销毁，不跨房叠加。
  - `RoomLayoutEditor.gd` 用「吸收法」：因 Node2D 不能直接接收 GUI 文件拖放，但 Godot 会把拖入的 .tscn 原生化实例为子节点 → `_sync_decorations_from_children()` 扫描子节点里的 `AnimatedSprite2D`，读 `scene_file_path`+`position` 写进 `_layout.decorations`（重建前+保存时各同步一次，避开 boss/inn 的 return）。`_build_decorations()` 从数据重建可点选/可拖拽的预览实例（`owner=edited_scene_root`）。`_rebuild()` 把 `_ensure_layout()` 提前到吸收之前修顺序坑。
- 验证：无头 `--editor` EXIT=0 零 SCRIPT ERROR，DecorationPlacement 注册为全局类；探针 `-s` 确认 Godot 4.7.1 实例后 `scene_file_path` 非空（`[res://test_deco/...tscn]`），吸收法数据来源可靠。插件默认输出 `res://Artssucai/gen/`（res:// 内，运行期 load 可用、导出会纳入）。探针脚本已清理。
- 用户操作（可视化）：插件选图→自动识别→生成 .tscn（落 res://Artssucai/gen/）→右侧素材库循环预览→从素材库把条目拖进 RoomLayoutEditor 的 2D 视口→摆放位置→Ctrl+S 保存（写入对应房间 .tres 的 decorations）→运行游戏进入该房即见动画播放。

## 修改·装饰视觉变换还原（补37）
- 用户报：运行游戏后放入场景的动画与 RoomLayoutEditor 里调整的不一样。
- 根因：「吸收法」`_sync_decorations_from_children` 只存了 `scene_path`+`pos`，**丢弃了 scale/rotation/flip**——在编辑器里缩放/旋转/翻转后保存，运行期一律不还原（变回 .tscn 默认 1.0/0°/不翻转）→ 看起来"不一样"。
- 位置逻辑本身是对齐的：Room 根 Node2D 无偏移，背景(base_pos)与装饰(def.pos)同挂 RoomManager 世界坐标，编辑器 RoomLayoutEditor 也 identity；两者一致，故只补变换不碰位置。
- 改动：
  - `DecorationPlacement.gd` 增 `scale_xy:Vector2=ONE` / `rotation_deg:float=0` / `flip_h:bool` / `flip_v:bool`。
  - `RoomLayoutEditor._sync_decorations_from_children` 用 `c as Node2D` 读 `scale`/`rotation`(弧度)→存 `rad_to_deg`；`flip_h/v` 来自 AnimatedSprite2D。
  - `_build_decorations` 与 `RoomManager._spawn_decorations` 还原：`scale=def.scale_xy` / `rotation=deg_to_rad(def.rotation_deg)` / `flip_h/v`。
- 关键坑（已修）：`Node2D`/`AnimatedSprite2D` **没有 `rotation_deg` 属性**，只有 `rotation`(弧度)。直接写 `c.rotation_deg` 报 "Invalid access to property 'rotation_deg' on AnimatedSprite2D" → 须用 `rotation` 读写、数据字段另存角度。
- 验证：无头 `--editor` EXIT=0 零报错；探针 `-s` `ROUNDTRIP_OK=true`（pos/scale/rotation_deg/flip_h/flip_v 序列化往返一致）。探针已清理。
