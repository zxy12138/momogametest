## 修第二轮编译报错（用户 F5 报，进关卡1才触发）
- **致命 Parser Error「Cannot infer type of path」**：`WeaponSystem.gd:174` `var path := FX + "weapon_fx_" + FXID[atk] + ".png"` —— `FXID` 是未类型化 `const Dictionary`，`FXID[atk]` 取值返回 Variant，整串表达式推断为 Variant，`:=` 失败。→ 显式类型 + 转字符串：`var path: String = FX + "weapon_fx_" + String(FXID[atk]) + ".png"`。**为什么进关卡1才报**：WeaponSystem 挂在 Player 的 Weapon 节点，Player 只在进战斗关卡时实例化 → 脚本解析才触发。
- **SHADOWED_VARIABLE_BASE_CLASS ×3（警告）**：`Game.gd:166/855` `var tr` 遮蔽 `Object.tr()` 方法 → 改名 `ct`；`Game.gd:610` `for name in picks` 遮蔽 `Node.name` → 改名 `afx`（含 lambda 内引用）。
- 预防性排查：全仓 `var X :=` 从 `.get()`/字典取值推断的隐患均已人工核对（`load_tex`/`_button`/`_card`/`_layout_path` 有明确返回类型；`_orbit`/`loadout` 是类型化数组；`String % Array` 推断 String）。`dir` 不是 Node 成员，无遮蔽。
- **教训**：① 未类型化 `const Dictionary` 取值 + 字符串拼接 → 必须显式 `String(...)` + 显式类型；② strict 模式下别用 `tr`/`name` 这类与 Object/Node 成员同名的局部变量。

  - `src/data/MapLayoutEditor.tscn`：根 Node2D + script。

- **验证**：探针 CELLS=22、LINKS=22、坐标往返误差<1px、拖拽归一化合理；全量编译 EXIT=0。
- **用户用法**：删 .godot 重开 → 打开 `res://src/data/MapLayoutEditor.tscn` → 拖格子/滚轮缩放/中键平移 → 「💾 保存布局」或 Ctrl+S → F5 按 M 看效果。

## MapLayoutEditor 左键拖不动修复（用户反馈）
- **根因**：脚本 `_input` 收不到编辑器 2D 视口的鼠标事件——Godot 编辑器不把视口输入转发给 @tool 场景脚本（被编辑器自身工具消费）。RoomLayoutEditor 能拖是因为走**编辑器原生拖拽**（节点 owner=edited_scene_root 后视口可直接点选拖动）。
- **修法**：删除 `_input/_mouse_scene/_hit_cell/_zoom_container` 整套脚本输入；`_make_cell` 给格子 root 设 `owner = get_tree().edited_scene_root`（原生可拖）；`_process` 每帧轮询格子 position 变化 → `_refresh_links_for` 刷新连线（@tool 下编辑器里 _process 正常跑）。滚轮缩放/中键平移用编辑器视口自带能力。
- **验证**：探针 LINK_FOLLOWS=true（格子移 (400,300) 连线端点跟随）、SAVE_NORM 界内。注意探针无头下 editor_hint=false，_process 守卫跳过，须直接调 _refresh_links_for 验证。
- **教训**：@tool 编辑器工具要「可拖拽」优先用 owner+原生拖拽+_process 轮询，别指望脚本 _input 收到视口事件。
