## 修 "Infinite loop detected"（Tween，3 次报错 = 3 把武器）
- **现象**：进第一关摆 3 把地面武器 → 3 次 `tween.cpp:420 Infinite loop detected`（切房后触发）。
- **根因**：`WeaponPickup._ready` 用 `get_tree().create_tween()`（**独立 Tween，不绑定节点**）+ `set_loops(-1)`。切房时武器被 group 清理销毁，`_spr` 失效但 Tween 仍存活 → 每帧步骤立即"完成"（目标无效）+ 无限循环重启 → Godot 单帧步进超限报 Infinite loop。**3 把武器 = 3 次**。
- **修复**：`get_tree().create_tween()` → **`create_tween()`（节点方法，绑定本节点，节点销毁自动 kill）**。`Pickup.gd`（set_loops(3)）同类顺手改。其余一次性 tween（无 set_loops）不受影响。
- **教训**：无限循环 Tween 必须用节点绑定的 `create_tween()`；独立 `get_tree().create_tween()` + 目标可能被销毁的场景会触发引擎的无限循环检测。错误信息 "Check set_loops() description" 指的就是这类情况。

## 修「Nonexistent 'String' constructor」狂刷（3 万条，RoomDockPanel:72）
- **根因**：`String(root.get("layer"))` —— `Node.get()` 返回 **Variant**，GDScript 4.7 里 `String(Variant)` 在运行时被解析为"调用 String 类的构造函数"→ 报 `Invalid call. Nonexistent 'String' constructor`。而 `_update_info` 在 `_process` 里每帧执行 → 狂刷 3 万条。
- **修复**：改用**全局函数 `str()`**（任何 Variant 都能转字符串，绝无构造函数问题）。波及清理：`RoomDockPanel.gd`(72 源头)、`EnemyHandle.gd`、`WeaponHandle.gd`、`Game.gd`(5 处：str(rid)/str(best.call)/str(ids[i])/str(pk.get))、`WeaponSystem.gd`(2 处 str(x)/str(FXID[atk]))、`GameManager.gd`(str(x))。
- **教训**：GDScript 里凡是参数是 **Variant**（`.get()`/`.call()`/Dict 索引/Array 元素/Dictionary.keys()）的转字符串，一律用 `str()` 别用 `String()`。`String(x)` 只在 x 是编译期可推断的具体类型时安全。MapData/MapUI/RoomLayoutEditor/MapLayoutEditor 里的 `String(...)` 是稳定运行代码（用户未报），未动避免回归。
