## SpriteTool 精灵图工作台（PySide6 GUI，用户需求）
- **需求**：精灵图处理工具——①自动抠图（选色+容差+羽化）②大窗口预览 ③动作单独切出 ④自由排列组合（每行 N 个）⑤按行动画预览。
- **产物**：
  - `tools/sprite_tool.py`（自包含单文件：SpriteToolCore 核心算法无 GUI 依赖 + SpriteToolWindow 暗色界面）
  - `tools/启动精灵图工具.bat`（pythonw 无黑窗，venv `E:\python project\开发Python插件管理分发系统\.venv`）
- **功能**：①颜色抠图（吸管取色/手动 RGB/容差 0-255/羽化 0-10px 高斯模糊）②切帧（auto 二维检测：先按行投影分行、再每行按列投影切帧；grid 网格手动行/列）③动作管理（自动按行分组、新建/上下移/删除/重命名、合并）④排列导出（每行帧数+帧间距 → 精灵表 PNG）⑤播放预览（QTimer 1-60fps，动作/全表，点击动作显示首帧）。
- **关键实现**：
  - 抠图：numpy 欧氏色距，`alpha = clip((dist - tol)/tol) * 255`（dist≤tol 透明，过渡带=tol）；羽化对 alpha 通道 GaussianBlur。
  - **容差语义坑**：第一版写成 `edge=255-tol`（距离 215 以内全透明）→ 近色内容被误抠（内容 alpha 93）。修正为透明阈值=容差本身。
  - **auto 检测坑**：第一版只按列投影 → 多行网格表只检出列数（4 列）。修正为二维检测（先分行再每行分列）→ 12 帧行序正确。
  - **QMessageBox 模态坑**：`_apply_frames` 弹窗在无显示环境阻塞 → 改 statusBar 非阻塞提示（真实体验也更流畅）。
  - **测试坑**：GUI 流程默认 key=(0,0,0) 黑没抠掉背景 → 1 帧（正常，用户需先吸管取背景色）；Python 管道输出缓冲+崩溃丢输出 → 用 `python -u` 定位崩溃点。
- **验证**：核心算法单测（抠图 alpha 0/255、auto 12 帧、grid 12 帧、排列导出尺寸对）；offscreen 完整 UI 流程（取色→抠图→12帧→3动作→播放→导出）全通；py_compile OK。
- **测试教训**：PySide6 脚本测试用 QT_QPA_PLATFORM=offscreen + python -u（无缓冲）；QMessageBox 模态框会阻塞 offscreen 测试，被测路径尽量用非阻塞提示或避开。

## SpriteTool v2 重写（14:43 用户反馈 4 个问题）
- **用户反馈**：①切帧横线对不齐 ②动作不能单独编辑帧 ③容差/羽化滑杆数值不跟随 ④要 3 个窗口（切帧/帧库/预览）
- **重写架构**：QSplitter 横向 3 列——①CropPanel（切帧参数+预览）②LibraryPanel（动作列表+帧池+选中动作帧区）③PreviewPanel（播放预览）。三个面板都有标题栏+边框，看起来像 3 个独立窗口。
- **bug ① 横线对不齐根因**：grid 模式固定 (c*fr_w, r*fr_h, (c+1)*fr_w, (r+1)*fr_h) 等分，DEATH 行因内容稀疏导致网格延伸到空白处看起来对不齐。auto 模式按列投影遇到"行内多内容带"（方块+标签+干扰线）被切碎。
  - **修复**：grid 模式加**紧凑边界**——每格内 x0/y0 紧贴首内容像素、x1/y1 紧贴末内容像素但 clip 到格子边界（保证 frame 不超出格子）。验证：9 行 70 帧，行 y0 完全对齐（10/94/178/.../682）。
  - auto 模式改用 np.where 紧凑边界 + 间隙合并（min_gap）。
- **bug ② 动作帧编辑**：每个 action 加 `frames: [int,...]` 字段（帧索引列表），LibraryPanel 的 acting 列表显示选中动作的帧（缩略图）+ 池子显示所有帧。支持按钮：加入帧、删除帧、上移/下移。Qt 内部拖拽 enabled（acting.setMovement(Snap)+DragDropMode.InternalMove）。
- **bug ③ 滑杆 label 跟随**：所有 Slider 加 `valueChanged.connect(lambda v: lbl.setText(...))`。容差→str(v)、羽化→f"{v} px"、fps→str(v)。
- **3 窗口架构**：主窗口 QSplitter 横向 3 列，每列 QFrame 包裹+标题栏（"① 切帧"/"② 帧库+动作"/"③ 播放预览"），用户可拖分隔条调整宽度。预览面板自带播放控制（动作下拉 + ▶播放 + fps 滑杆 + 缩放）。
- **验证**：编译零错；grid 9×8 → 70 帧行对齐；offscreen UI 流程（slider label/动作编辑/预览同步）全过。
- **教训**：UI 复杂功能开发要分层——核心算法（无 GUI 依赖）单测 + UI 流程 offscreen 测试用 `python -u`（Python 管道缓冲+崩溃丢输出）+ 避免 QMessageBox 模态阻塞 offscreen 测试。横线对齐类 bug 的根因通常是"边界算法不对齐内容"，用紧凑边界+clip 解决。
