## 23:25 修复中文编码崩溃（subprocess GBK 解码）
- **报错**：`UnicodeDecodeError: 'gbk' codec can't decode byte 0x80`（subprocess 的 _readerthread 读取 ffmpeg 输出时崩）。
- **根因**：`probe_video` 的 `subprocess.run(..., text=True)` 在 Windows 上用**默认 GBK** 解码 ffmpeg 的 stderr；ffmpeg 输出视频元数据/中文路径时含 **UTF-8 字节**（如 0x80 起头），GBK 无法解码 → 崩。**不是"不支持中文"，是编码不匹配**。
- **修复**：`subprocess.run(..., text=True, encoding="utf-8", errors="replace")`。中文路径/中文元数据实测通过（64×64 12fps argb / 中文 title 元数据均正确 probe）。脚本其余 subprocess 调用输出都重定向 DEVNULL，无需改。
- **经验**：Windows 上 subprocess 读外部工具输出，务必 `encoding="utf-8", errors="replace"`（或读 bytes 再 decode），否则默认 GBK 遇到 UTF-8 中文字节即崩。传参（中文路径）Python3 用 CreateProcessW 无碍，Git Bash 里测中文路径会被 shell 编码干扰（不可靠），要用 Python 脚本文件测。

## 00:07 修复门改造的两处问题

- **①判定框隐藏同步**：门的设置常量/静态方法从 RoomManager **移到 BlockedHandle**（`HIDE_DOOR_VISUAL_SETTING`/`is_door_visual_hidden`/`set_door_visual_hidden`）避免 DoorHandle→RoomManager 循环 class_name 依赖；DoorHandle._redraw 里 `if not BlockedHandle.is_door_visual_hidden():` 画判定框（编辑器与运行期一并隐藏）。
